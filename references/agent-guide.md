# 执行指引

## 工作顺序

1. 按 [采集合同](collection-contract.md) 自动选择目标公司主体，取得 `analysis-input.json`、`talent-structure.json`、`talent-data-panels.md` 和 `talent-attention-summary.md`；不向调用方请求候选主体、样本分组或报告确认。
2. `analysis-input.json` 是唯一事实源。业务与人才分支各自用全量非空 JD 建立覆盖账；每个岗位保留 ID、链接、原文锚点，并记录为形成判断或未形成判断。
3. 业务账本按业务对象、市场或用户、可观察动作、经营变量和取舍建账；人才账本按角色族、城市、经验、薪资、用工与实习状态、显性技能、能力证据和原始关键词建账。人才信号只按 [分支证据账本合同](branch-ledger-contract.md) 取数。
4. 两个隔离分支分别做横向分析后，按 [读者语言合同](reader-language-contract.md) 建立本分支叙事卡并成稿；不得读取对方账本、主题、标题或正文。人才分支先原样嵌入 `talent-data-panels.md`，保留角色族岗位引用中的全量岗位名称和岗位链接，再利用每张图后的洞察写对比和招聘含义，最后原样嵌入 `talent-attention-summary.md`；覆盖、字段、原文锚点和限制集中处理，不在每个段落重复。
5. 按 [交付合同](delivery-contract.md) 落盘并校验。

## 证据边界

- 招聘需求不等于经营结果、组织规模、在岗能力或未来变化。
- 每个战略判断至少由两个相互独立的角色、业务对象或职责锚点交叉支持；否则降为直接事实。
- 城市、薪资、岗位数、标题或 AI 关键词只能作为结构线索。
- 面向读者的正文不用内部字段名、岗位 ID 或裸链接；未知写“未观察到”并给出验证问题。

## 分支隔离

| 分支 | 读者 | 输入 | 回答的问题 |
|---|---|---|---|
| 业务 | 业务负责人 | 原始快照、业务证据账本、业务对象和职责链原文 | 当前靠什么业务动作获得增长、正在押注什么、最该核实的经营取舍是什么？ |
| 人才 | 组织与招聘负责人 | 原始快照、`talent-structure.json`、人才证据账本、岗位画像、技能、能力证据和关键词原文 | 这批岗位反映出怎样的角色、地域、经验、薪酬与用工、能力配置和实习梯队分布？ |

协调 Agent 只负责分发、归档、报告索引和合同校验，不新增业务判断或合并正文。
