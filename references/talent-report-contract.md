# 人才报告中间层合同

`talent-structure.json` 是人才报告唯一的结构化中间层。它由内置采集器在写出 `analysis-input.json` 时自动生成；调用方只输入公司名，不运行脚本、不确认样本分组、不选择报告口径。

其中 `talentSignals` 是人才分支的原始信号索引：`skills` 仅汇总岗位详情明确给出的 `skills` 与 `requirementTags`；`abilityEvidence` 仅保留带岗位链接的职责/产出原文句；`keywords` 仅索引岗位名称、`skills` 与 `requirementTags` 原词。三类信号必须分别呈现，不能互相替代或从常识推断。

## 样本边界

- 一条公开岗位对应一条岗位记录；同一 JD 的重复发布不得丢弃，只能在“JD 模板”层合并并保留关联岗位数和岗位链接。
- 只有经过换行和行尾空格规范化后完全相同的 JD 才能合并为一个模板。不得用语义相似度把不同 JD 合并。
- 无 JD 的岗位仍计入岗位总数，并列入“JD 未形成”清单；不得据此产生能力或薪资判断。
- 职位名称或公开字段含“实习”或 `intern` 的岗位归为 `internship`。其余岗位归为 `nonIntern`，面向读者称“非实习岗位”，不得擅自称为“社招”。
- 主人才结构、岗位模板分布、薪资排序和“重点关注岗位”只使用 `nonIntern`。实习岗位单列为“实习人才观察”，不参与前述分母、排序或角色比较。

## 薪资与关注信号

- 保留职位详情中的薪资原文，分别解析 K/月与元/月的非实习月薪区间、实习日薪区间和时薪区间；`面议`、缺失和未识别格式保留原文，不用“未采集”描述。
- 非实习月薪、实习日薪、时薪和面议/未解析状态是彼此独立的口径，不得互相换算或混入同一分母。不同城市、角色、经验、薪数或币种也不得被假定为可直接比较。
- 非实习月薪以每条公开区间的中点计算 P50 和中间 50%，并按角色、城市和经验切片；经验切片不是同角色晋升薪酬曲线。切片必须显示岗位数和已观察薪数。
- `·14薪` 等薪数单独分布；年固定现金估算仅在同时观察到月薪区间和薪数时，按“月薪区间中点 × 薪数”计算，明确不含奖金、福利和股权。它不是个人实际总包、市场水平、预算或招聘优先级。
- 标题含负责人、总监、总经理、总裁、VP、Head、Chief、CXO 或合伙人的岗位列为“管理/负责人标题信号”。它们不是已确认高管任命、组织层级或业务优先级。
- “重点关注岗位”展示高薪信号和管理/负责人标题信号的并集；每项必须给出岗位链接、薪资原文、岗位职责锚点和适用的限制说明。

## HR 数据维度

`workforceDimensions` 是人才报告的数据底座：`roleFamilies`、`cities`、`experience`、`experienceUnclassified`、`internshipCommitment`、`employment` 和 `compensation` 均由全量岗位快照计算。`compensation` 包含非实习月薪中点带、薪数、年固定现金估算、角色/城市/经验切片、实习日薪与时薪数量。`experience` 只统计非实习岗位中可识别为年限或“经验不限”的要求；非标准值进入 `experienceUnclassified` 并在限制中说明。实习岗位的到岗天数、时长或在校要求只进入 `internshipCommitment`，不得混入经验层级。每个分布项保留岗位数和岗位 ID；报告只能描述已观察到的分布，不能把岗位数写成团队规模、编制、优先级或市场供需。

`talentSignals` 补足能力配置：`skills` 只来自 `skills` 与 `requirementTags`，`abilityEvidence` 只来自带岗位链接的职责原文，`keywords` 只索引原词。三者分别说明覆盖范围，不互相替代，也不能把关键词频次写成能力强度。

`talent-data-panels.md` 由 `scripts/render-talent-data-panels.mjs` 从 `talent-structure.json` 确定性生成，包含角色、地域和非实习月薪中点三张 Mermaid 统计图，每张图后都按“结构 -> 可能招聘意图 -> 最该验证的问题”写洞察。角色结构后必须提供“角色族岗位引用”，列出每个角色族的全量岗位名称和岗位链接；归类表与正文都不得只给抽象角色名而省略可追溯依据。薪酬面板依次呈现公开月薪口径、薪数、年固定现金估算、月薪中点带、角色/城市/经验切片、实习日薪与时薪；能力配置展示层排除福利、办公方式和雇主属性等非能力标签，但原始标签仍保留在结构化数据和账本中。每个百分比都以“百分比（岗位数/分母）”呈现；禁止模型手算、改写或选择性删去面板条目。

`talent-attention-summary.md` 从相同结构化数据确定性生成，按已出现的角色、地域、经验与用工和能力信号提炼“值得关注”。它的“可能招聘侧意图”是受限假设，不是对公司策略、优先级或组织事实的断言；报告必须以该文件结束。

## 人才数据分析报告成稿

报告服务于组织与招聘负责人进行人才盘点和招聘信息解读，不替读者作出招聘、学习或经营决策。思维导图后先原样嵌入 `talent-data-panels.md`，正文再按已观察到的数据维度解释差异和招聘含义，而不是复述表格或按固定数量的观点组织；在 `## 依据与限制` 后原样嵌入 `talent-attention-summary.md` 作为报告结尾：

- `人才结构`：角色族、岗位数和可见的结构集中度。
- `地域与布局`：城市分布及其岗位事实；不得推断设点原因或区域优先级。
- `经验与梯队`：经验层级分布，说明可见梯队，不将职位要求写成团队现状。
- `薪酬与用工`：非实习月薪中点带、薪数与年固定现金估算、角色/城市/经验切片、实习日薪及其独立口径；不把跨角色、跨城市或跨单位差异写成统一薪酬结论。
- `能力配置`：显性技能、职责动作和关键词的岗位覆盖与差异；不得把要求升级为已具备能力。
- `实习梯队`：存在实习岗位时单列岗位、城市、经验和能力线索；没有实习岗位时写“未观察到实习岗位”。
- `依据与限制`：用不超过三条说明主体、采集时间、完整 JD 覆盖、分类边界和不可比较项；不得在每个数据维度后重复同类免责声明。
- `值得关注`：仅汇总已出现的结构信号，并说明其可能的招聘侧意图和下一步验证重点；不限制条数，不把假设写成事实。

角色协作或共同交付只能用于解释某一数据维度，不能取代上述 HR 数据主线。任何“该公司正在”“一定需要”“优先招聘”“高管布局”“薪资领先”等结论均须删除或改写为受限的岗位观察。

报告开头使用 Mermaid 思维导图，但导图必须反映上述数据层次，不能代替证据表。
